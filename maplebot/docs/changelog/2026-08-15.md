# 2026-08-15 把 YOLO 模型接入旧 maplebot 项目

## 变更概述
把 new 项目训练的 YOLO 模型（best.pt）接入旧 maplebot 项目，替代原 outline（描边）检测。
旧项目全套挂机能力（巡逻+血量+复活+安全）复用，YOLO 提供更准的怪物识别。

## 背景
- new 项目（maplestory-worlds-automation）只有 YOLO 识别怪，无挂机框架
- 旧 maplebot 项目有完整挂机框架，但怪物检测用 outline 不够准
- 验证发现旧项目已有完整 YOLO 接口（vision/yolo_mobs.py + mobs.py make_detector），
  接 best.pt 只需改配置——但 best.pt 是 6 类模型（character/environment/item/mob/npc/ui），
  旧项目 fsm 不区分类别一律攻击，需加 mob-only 过滤

## 修改详情

### 1. 复制模型
- 新增 `weights/best.pt`（从 new 项目复制，6 类：character/environment/item/mob/npc/ui）
- 新增 `weights/best.onnx`（ONNX 格式，CPU 推理备选）

### 2. `maplebot/vision/yolo_mobs.py` — 加类别过滤
- `YoloMobDetector.__init__` 加 `keep_classes` 参数（类别名列表，默认 None=不过滤）
- `detect()` 只输出 `name in keep_classes` 的检测结果
- 原因：best.pt 标出 item/npc/character/ui，fsm 不分类别一律攻击，不过滤会去打物品和 NPC

### 3. `maplebot/config.py` — VisionCfg 加字段
- `VisionCfg.yolo_keep_classes: Optional[List[str]]`，默认 `["mob"]`
- `load_config` 解析 `yolo_keep_classes`（list=过滤清单，空字串/False=关闭过滤）
- 默认 ["mob"] 正好枫谷用，用户无需配置

### 4. `maplebot/vision/mobs.py` — make_detector 传参
- `YoloMobDetector(..., keep_classes=vision_cfg.yolo_keep_classes)`

### 5. `config/local.yaml` — 启用 YOLO
```yaml
vision:
  mob_detector: yolo
  yolo_model: weights/best.pt
  yolo_confidence: 0.6
```
- local.yaml deep-merge 覆盖 default.yaml 的 outline 设置
- 保留已有的 regions（用户之前框选的）

## 修改文件清单
- 新增：`weights/best.pt`、`weights/best.onnx`
- 修改：`maplebot/vision/yolo_mobs.py`、`maplebot/vision/mobs.py`、`maplebot/config.py`、`config/local.yaml`
- 删除：无

## 测试结果
- `py_compile` 三个改动文件全过
- `pytest tests/test_config.py tests/test_mobs.py tests/test_remote_mobs.py` — 38 passed
- 配置加载验证：`mob_detector: yolo` 生效，`yolo_keep_classes: ['mob']`，YoloMobDetector 实例化成功
- fixture 图（旧枫谷画面）best.pt 0 检测——预期（域不匹配，best.pt 训练于新项目画面）
- 端到端需真实游戏画面验证（用户操作）

## 风险
- best.pt 训练于 new 项目画面，旧项目游戏窗口分辨率/画面不同时精度可能下降
  → 实测，不准则用旧项目画面重新采集训练
- torch 2.11.0+cpu 无 CUDA，CPU 推理较慢 → 可用 best.onnx + onnxruntime，或装 CUDA 版 torch
- local.yaml 已有 regions 疑似框错（minimap 267x276 过大）→ 用户需重跑 calibrate.py 重框

## 后续（用户操作）
1. `python tools/calibrate.py --write` 重框 regions（minimap/HP/MP/EXP/playfield）
2. `python tools/record_route.py --profile config/profiles/<地图>.yaml --out route.yaml` 录巡逻路线
3. 写目标地图 profile（复制 example.yaml 改，填巡逻点+技能+药水）
4. `python tools/doctor.py` 体检
5. `python main.py --profile <地图>.yaml --dry-run` 看决策
6. `python main.py --profile <地图>.yaml` 实机挂机

## 关键设计决策
- **把 YOLO 接到旧项目而非反向移植**：旧项目已有完整 YOLO 接口 + 全套挂机能力（589 测试），
  接 best.pt 只需改配置+加类别过滤。反向（new 项目移植全套）要造 10+ 模块，工作量 10 倍
- **加 keep_classes 过滤而非改 fsm**：fsm 不分类别攻击是既有设计（outline detector 也这样），
  在检测层过滤最小侵入，不动决策层和 589 个测试
- **yolo_keep_classes 默认 ["mob"]**：用户无需配置，恰好枫谷用；想关过滤设空字串即可

## 追加：寻怪功能（mode: hunt）移植

### 变更概述
把 new 项目 auto.py 的"智能寻找怪物"功能移植到旧项目，作为 `mode: hunt` 与巡逻模式并列。

### 背景
- new 项目有寻怪功能（无怪自动左右晃+返回原位），旧项目只有巡逻（需录路线）
- 用户要求 config 切换两模式，参数全内置默认不暴露
- 寻怪是"没录路线时的兜底"，适合怪物随机刷在同一片平地的地图

### 修改详情

**`maplebot/config.py`**
- `Profile` 加 `mode: str = "patrol"`（patrol/hunt）
- `load_profile` 解析 mode + 校验值
- waypoints 必填校验放宽：hunt 模式不要求 waypoints

**`maplebot/brain/fsm.py`**
- `Runtime` 加 hunt 状态字段（last_mob_time/hunting/hunt_start/hunt_origin_x/hunt_dir/hunt_moves）
- 加 HUNT_* 内建常量（触发2秒/超时10秒/走0.3秒/返回0.5秒/3次换向），不进 config
- `decide` 开头：有怪统一重置 hunt 状态（last_mob_time + hunting=False）
- `decide` 末尾巡逻入口前：`mode == "hunt"` 分支走 `_hunt_decide`
- `_hunt_decide`：无怪>2秒开始晃→Move左右（每3次换向）→超时返回原位→有怪停

**`tests/test_fsm.py`**
- 加 `hunt_profile` fixture + 5 个 hunt 测试（触发等待/开始寻怪/换向/发现怪停止/超时返回）

### 寻怪参数（全内置，用户零配置）
| 参数 | 值 | 说明 |
|------|-----|------|
| HUNT_TRIGGER_SECONDS | 2.0 | 无怪超此秒才找 |
| HUNT_MAX_SECONDS | 10.0 | 一趟寻怪最长 |
| HUNT_MOVE_SECONDS | 0.3 | 每次按方向键秒数 |
| HUNT_RETURN_SECONDS | 0.5 | 返回原位走更久 |
| HUNT_SWITCH_EVERY | 3 | 同方向走几次换向 |

### 修改文件
- 改：`maplebot/config.py`、`maplebot/brain/fsm.py`、`tests/test_fsm.py`
- 删：无

### 测试结果
- `pytest tests/test_fsm.py -k hunt` → 5 passed
- `pytest`（全套）→ 593 passed, 1 skipped（原589+新增5，无回归）

### 用法
profile 设 `mode: hunt` 即用寻怪（不用录路线）：
```yaml
mode: hunt
attack:
  key: ctrl
  range_px: 320
# 不需要 patrol.waypoints
```
默认 `mode: patrol` 保持原行为。
